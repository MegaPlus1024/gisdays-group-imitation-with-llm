# Итоговый отчёт о системе локальных LLM-агентов

## 1. Назначение

Проект проверяет, могут ли несколько локальных агентов согласованно выполнять
одну задачу. Агенты работают с документами, файлами и структурированными
фактами, передают результаты между ролями, исправляют ошибки и завершают
работу только после выполнения всех требований.

Каждому агенту назначены:

- роль;
- собственная история;
- разрешённые инструменты;
- доступные файлы и общие факты;
- зависимости от результатов других агентов;
- условия завершения.

Все действия сохраняются в журнале. Поэтому по завершении можно проверить не
только итог, но и путь, которым агенты к нему пришли.

## 2. Устройство системы

### Основная среда выполнения

Главная реализация находится в
`src/agent/autonomous_multi_agent_runtime.py`.

Она отвечает за:

- состояние каждого агента;
- последовательность ходов;
- вызов правил взаимодействия с моделью;
- проверку предложенного действия;
- выполнение разрешённого инструмента;
- добавление результата в историю;
- хранение общих файлов и фактов;
- проверку условий завершения.

Агенты ходят по очереди. Такой порядок делает испытания повторяемыми и
упрощает разбор журнала. Он не означает одновременный вывод нескольких
моделей.

### Правила взаимодействия с моделью

На каждом ходу модель получает:

- описание текущей роли;
- доступные инструменты;
- необходимую часть истории;
- последнее наблюдение;
- текущее состояние зависимостей;
- требования к завершению.

Ответ должен содержать одно действие в формате JSON. Среда выполнения не ищет
JSON внутри произвольного текста и не исправляет структуру ответа за модель.
Некорректный ответ становится наблюдаемой ошибкой, после которой модель может
предложить исправленное действие.

Для проверок без модели используются детерминированные правила. Они проходят
через те же состояния, инструменты и проверки, что и локальная модель.

### Реестр инструментов

Среда использует существующие `ScriptRegistry` и `ScriptExecutionBridge`.
Реестр включает ограниченные операции для:

- чтения заранее подготовленных статей;
- чтения, создания и передачи файлов;
- работы с локальными документами;
- выполнения простых разрешённых команд;
- публикации и чтения общих фактов;
- ожидания зависимости;
- завершения работы агента.

Перед выполнением проверяются имя инструмента, параметры, права роли и
допустимый путь. Файловые операции используют только разрешённые относительные
каталоги.

### Общая рабочая среда

Общая среда хранит:

- подготовленные статьи и документы;
- рабочие файлы;
- опубликованные факты;
- владельца и источник каждого факта;
- состояние зависимостей;
- выполненные требования.

Публикация факта требует точного значения из выбранного подтверждения. Среда
проверяет идентификатор подтверждения, источник, поле, полномочия роли и
нормализованное значение. Сокращённый или перефразированный факт отклоняется.

### Проверки и ограничения

| Проверка | Назначение |
| --- | --- |
| Права роли | Запрещает инструмент, которого нет в списке роли |
| Параметры | Проверяет обязательные поля и типы |
| Пути | Не допускает выход из разрешённого каталога |
| Происхождение факта | Связывает публикацию с наблюдённым источником |
| Точное значение | Не принимает сокращение или пересказ |
| Повторение | Останавливает неизменяемые неуспешные повторы |
| Зависимости | Не позволяет завершить задачу до появления нужных данных |
| Завершение | Требует выполнения всех условий сценария |

### Подтверждающие данные

Запуск может сохранять:

- журнал ходов в JSONL;
- сводку каждого испытания;
- общую сводку;
- сведения о запросах модели;
- результаты измерения ресурсов;
- manifest с размерами и SHA-256.

Секреты и произвольное содержимое запросов в итоговые диагностические поля не
копируются.

## 3. Проверка поведения моделей

Полный набор содержит семь сценариев и пять повторов каждого сценария.

| № | Сценарий | Технический идентификатор | Что проверяется |
| ---: | --- | --- | --- |
| 1 | Передача файла после чтения статьи | `article_file_handoff_v2` | Один агент извлекает точное значение, создаёт файл и передаёт его другой роли |
| 2 | Восстановление после отсутствующего файла | `office_shared_fact_recovery_v2` | Агент получает ожидаемую ошибку, выбирает правильный источник и публикует факт |
| 3 | Граница полномочий и точная передача | `role_boundary_exact_handoff` | Действие выполняет только разрешённая роль, а идентификатор передаётся без изменения |
| 4 | Исправление некорректного действия | `malformed_action_recovery` | Модель исправляет форму следующего действия после отказа |
| 5 | Конфликт источников | `conflicting_grounded_facts` | Агенты выбирают источник с подходящими полномочиями |
| 6 | Зависимости и защита завершения | `dependency_progress_and_finish_guard` | Агент ждёт необходимые данные и не завершает работу раньше времени |
| 7 | Длительная многофакторная задача | `long_horizon_multi_fact_retention` | Агенты сохраняют несколько фактов, создают файлы, исправляют ошибки и собирают итоговое состояние |

Сценарии работают с локально подготовленными данными. Они не обращаются к
открытому интернету или реальным пользовательским системам.

## 4. Условия прохождения

Модель проходит полный набор только при одновременном выполнении всех условий.

| Условие | Порог |
| --- | ---: |
| Успешные испытания | не менее 32 из 35 |
| Минимум в каждом сценарии | не менее 4 из 5 |
| Выполненные требования с подтверждёнными источниками | 100% |
| Нарушения прав ролей | 0 |
| Факты без подтверждённого источника | 0 |
| Неизменяемые неуспешные повторы | 0 |
| Успешное восстановление после ожидаемых ошибок | не менее 90% |
| Точность передаваемых значений | 100% |
| Публикации от роли без полномочий | 0 |
| Ожидание необъявленных зависимостей | 0 |

Высокий общий результат не компенсирует провал обязательного длительного
сценария.

## 5. Результаты

| Модель | Успешные запуски | Длительный сценарий | Итог |
| --- | ---: | ---: | --- |
| Qwen3-14B Q5_K_M | 30 из 35 | 0 из 5 | Обязательный критерий не выполнен |
| Mistral Small 3.2 24B Instruct Q4_K_M | 30 из 35 | 0 из 5 | Обязательный критерий не выполнен |
| Qwen3-30B-A3B-Instruct-2507 Q4_K_M | 30 из 35 | 0 из 5 | Обязательный критерий не выполнен |
| Qwen3.6-27B Q5_K_M | 35 из 35 | 5 из 5 | Все критерии выполнены |

Первые три модели успешно завершали короткие и средние сценарии, но ни разу не
завершили длительную многофакторную задачу. Qwen3.6-27B Q5_K_M прошла все 35
испытаний, включая пять повторов длительного сценария.

Дополнительный запуск использовал те же определения сценариев, подсказки,
проверки и правила подсчёта. Специального упрощения под модель не было.
Исходное сравнение трёх моделей не переписывается и остаётся отдельным
зафиксированным результатом.

Результаты относятся к конкретным контролируемым сценариям. Они не являются
общей оценкой интеллектуальных возможностей моделей.

## 6. Результаты измерения ресурсов

Сравнимые профили использовали один сервер, одну модель, контекст 12288, один
параллельный слот, три прогревочных запроса и по десять измеряемых запросов
трёх размеров.

### Qwen3.6-27B Q5_K_M

| Показатель | Значение |
| --- | ---: |
| Размер GGUF | 19 509 790 944 bytes |
| Память GPU после загрузки | 19 386 MiB |
| Максимальная память GPU | 19 410 MiB |
| Оставшаяся память GPU | 5 057 MiB |
| Средняя задержка короткого запроса | 2 970 ms |
| Средняя задержка среднего запроса | 7 031 ms |
| Средняя задержка длинного запроса | 13 250 ms |
| Максимальная мощность | 148.43 W |
| Максимальная температура | 87 °C |
| Успешные измеряемые запросы | 30 из 30 |
| Слои на GPU | 65 из 65 |

Профиль получен на NVIDIA RTX PRO 4000 Blackwell с 24 467 MiB памяти. Это
описание одной проверенной машины, а не универсальное аппаратное требование.

### Сравнение профилей

| Наблюдение | Модель |
| --- | --- |
| Наименьшее потребление памяти GPU | Qwen3-14B Q5_K_M |
| Наибольший запас памяти GPU | Qwen3-14B Q5_K_M |
| Наименьшая задержка запросов трёх размеров | Qwen3-30B-A3B-Instruct-2507 Q4_K_M |
| Наименьшая максимальная мощность | Qwen3-30B-A3B-Instruct-2507 Q4_K_M |
| Наименьшая максимальная температура | Qwen3-30B-A3B-Instruct-2507 Q4_K_M |
| Единственная модель, прошедшая обязательный критерий поведения | Qwen3.6-27B Q5_K_M |

Более быстрая или экономичная модель не обязательно лучше выполняет
многошаговую задачу. Поэтому единый синтетический балл для скорости, памяти и
корректности не вычисляется.

## 7. Область применимости

Набор испытаний хорошо проверяет:

- разделение обязанностей между ролями;
- работу с документами и точными значениями;
- передачу результатов между агентами;
- зависимости между этапами;
- выбор источника с подходящими полномочиями;
- исправление действия после ошибки;
- строгие условия завершения;
- возможность проверить каждый ход.

Отдельной проверки требуют:

- длительная непрерывная работа;
- одновременная работа нескольких пользователей;
- изменение целей во время выполнения;
- отказоустойчивость и восстановление сервиса;
- мониторинг, обновление и откат версий;
- защита реальных данных;
- стоимость эксплуатации;
- непредусмотренные входные данные.

Полученный результат является важной проверкой функциональной корректности,
но не заменяет полный комплекс эксплуатационных испытаний. Это ограничение не
означает низкого качества набора: его задача — проверить корректность поведения
агентов в заданных сценариях.
